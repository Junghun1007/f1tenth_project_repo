# semi_slam

정답 트랙(4 m × 4 m)을 일정 속도로 여러 바퀴 돌며 **트랙 위 내 위치(중앙선 기준 몇 m 지점, 옆으로 몇 cm)**를 추정하고,
정지선 S와 바퀴 수만으로 **오도메트리 보정 값(자이로 배율, 속도별 거리 배율)**을 구하는 패키지.
cone_drive_test에서 주행에 필요한 부분(BEV, IMU 안정화, 차선 인식, Stanley, duty-only 종방향, 안전 전환)만 복사한 독립 패키지다.

## 빌드·실행 (Jetson)

```bash
CMAKE_BUILD_PARALLEL_LEVEL=1 MAKEFLAGS=-j1 colcon build --executor sequential --packages-up-to semi_slam --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash && ros2 launch semi_slam semi_slam.launch.py
```

브라우저: `http://<jetson-ip>:8766` (cone_drive_test와 동시에 켜지 않는다: 카메라·VESC를 같이 쓴다)

## 주행 순서

0. (처음 한 번, 카메라를 다시 달았을 때) **카메라 yaw 맞추기**: 차를 정지선 S 앞 0.3~1.0 m에 차선과 나란히, 가운데에 세우고
   **yaw 자동 측정**. 2초 동안 양쪽 차선과 정지선이 기울어 보이는 각도를 재서, 둘이 1° 안에서 맞으면 `camera.yaw_deg`를 고친다.
   다시 눌렀을 때 0° 근처면 끝. 직접 넣을 때는 상단 **카메라 yaw [크기] [+ 왼쪽 / − 오른쪽]** (BEV 변환을 바로 다시 만든다).
   값은 `<data_dir>/camera_yaw.json`에 남아 다음 실행에도 쓴다. BEV 패널의 "차선 각도·정지선 기울기"로 언제든 확인.
1. 상단 **방향**을 고르고, 차를 **아래쪽 직선이 시작되는 곳 도로 가운데**에 놓는다 (지도에 초록 화살표로 표시).
   - 반시계: 왼쪽 아래 코너가 끝나는 x ≈ 1.0 m에서 오른쪽(+x)을 보고
   - 시계: 오른쪽 아래 코너가 끝나는 x ≈ 3.0 m에서 왼쪽(−x)을 보고
   - 두 경우 모두 정지선 S가 약 1 m 앞. 앞범퍼가 다른 곳이면 `slam.start_shift_m` (진행 방향 앞 +)
   정지선 S까지 약 1 m는 가속만 하고, **S를 처음 지나는 순간부터** 기록·매핑·바퀴 세기를 시작한다. 그때 위치는 S, 방향·옆 위치는 BEV 차선으로 잡는다.
2. 출발 전 점검 칩이 모두 초록이 될 때까지 기다린다 (카메라 자세 측정, 차선 모델).
3. 상단에서 **일정 속도**(m/s)와 **바퀴 수**를 넣고, IMU 안정화(전체/끄기), 정지선 위치 보정(켬/끔)을 고른다.
4. **주행 시작** → 정지선 S를 지날 때마다 바퀴를 세고, 목표 바퀴를 채우면 정지 → 수동 주행으로 넘어간다.
5. 멈추면 기록을 저장하고 **보정 값을 계산해 누적 평균으로 반영**한다 (화면 상단 상태 문구, 보정 이력).
   이상하면 **보정 되돌리기**. 중간에 정지하면 기록만 저장하고 보정하지 않는다.

같은 속도를 여러 번, 그리고 속도를 바꿔(예: 1.0 / 1.2 / 1.4 / 1.6) 돌리면 속도별 거리 배율 표가 채워진다.

## 위치 추정·보정 방법

트랙은 이상적이지 않다(직선마다 폭 ±1.5 cm, 테이프 휨 ±1°)고 보고, 지도 모양에 맞추지 않는다.

- 자유 적분: `x += v·k(v)·cos ψ·dt`, `ψ += g·(ω − b0)·dt`. `b0`는 출발 직전 정지 중에 잰 자이로 영점.
- **위치 추정 (화면의 메인 궤적)**: 진행 방향 = 마지막 정지선 S 통과 후 거리로 찍은 **지도 중앙선 위 지점**,
  옆 = BEV에서 차 바로 앞(0.1~0.5 m) 차선 가운데 (코너에서 가까운 선도 휘어 보이면 이전 값 유지), 방향 = 자이로.
  S를 지날 때마다 진행 방향 위치를 S로 다시 잡는다. 자유 적분 궤적은 비교용으로 흐리게 같이 그린다.
- **보정** (목표 바퀴 완료 시):
  - 자이로 배율 = 360° × 바퀴 수 ÷ (S → S 원값 회전량). 처음·마지막 S에서 차가 차선 대비 비스듬했던 만큼은 뺀다.
  - 거리 배율(속도별) = 중앙선 한 바퀴(11.31 m) × 바퀴 수 ÷ (S → S 원값 거리). 주행 라인 차이로 ±1% 정도 흔들린다.
  - 이전 값과 **바퀴 수 가중 평균**으로 갱신 (이전 가중치 최대 30바퀴). 이전 값과 2% 넘게 다르면 그 항목은 반영하지 않고 이유를 남긴다.
  - 잔여 영점은 같은 속도 주행으로는 배율과 구분이 안 되어 추정하지 않는다.
- **주행 중 yaw 검산**: 직선에서 "BEV 차선 각도"와 "차선 안 옆 위치가 밀리는 속도로 구한 실제 비스듬함"의 차이 = BEV가 더 기울어 보이는 각.
  0° 근처면 카메라 yaw가 맞다. 차를 세운 자세와 상관없이 나오므로 정지 측정의 검산용.
- 정지선 S: 관측 거리로 통과 지점을 예측해 바퀴를 센다. 관측한 정지선의 중앙선 위 위치가 S에서 1.2 m 밖이거나,
  바퀴 거리가 한 바퀴의 (1 ± 25%) 밖이면 오인식으로 무시한다.
- 바퀴 표: 거리, **S 도착 오차**(바퀴 거리 − 중앙선 한 바퀴 = 위치 추정의 앞뒤 오차), 회전(보정 적용, 정답 360°), 평균 옆 위치, 자유 적분의 S 오차.
- 지도 대비 차선 점 RMS는 참고용으로만 계산한다 (보정 기준 아님).
- 예전 형식(카메라 각도·BEV 축척을 Nelder–Mead로 찾던) 보정 값은 시작할 때 `backup_<시각>/`으로 옮기고 기본값에서 시작한다.

## 저장 위치 (`slam.data_dir`, 기본 `~/semi_slam_data`)

| 파일 | 내용 |
|---|---|
| `calibration.json` | 지금 쓰는 보정 값 (다음 실행에도 이어서) |
| `calibration_history.jsonl` | 보정 이력 (반영/안 함/되돌림, 그 주행에서 구한 자이로·거리 배율, yaw 검산) |
| `camera_yaw.json` | 웹에서 바꾸거나 자동 측정한 카메라 yaw (yaml보다 우선) |
| `odometry_calibration.yaml` | 다른 패키지(cone_drive_test 등)가 읽기 쉬운 형식 |
| `runs/<날짜_시각_v속도>/` | `meta.json`, `speed.csv`, `gyro.csv`, `lanes.csv`(차선 점·정지선 거리), `crossings.csv`, `laps.csv`, `corrections.csv`, `trajectory.csv`, `calibration.json` |

`meta.json`에는 주행 당시 주요 파라미터(카메라 yaw, 코너 오프셋, 안정화, 속도, 방향 등)도 남는다.
기록으로 보정만 다시: `ros2 run semi_slam semi_slam_recalibrate <기록 폴더> [--apply]`.

## 정답 트랙

`maps/track_4x4.csv` (`line,x_m,y_m`: outer, inner, center, stop_S, start_T1). 치수는 사용자 트랙 그림에서 읽은 값으로
`tools/make_track_csv.py`에 적혀 있다. 선 위치는 테이프 가운데이고, 차선 폭은 실측(테이프 안쪽 64 cm + 테이프 3 cm = 가운데 간격 67 cm)을 쓴다
(바깥 선 0.165 m 안쪽·코너 R 0.62, 안쪽 선 0.835 m·r 0.174, 정지선 x 1.97, 출발선 x 2.03).

## 호스트 테스트 (ROS 없이)

```bash
cmake -S src/semi_slam/test/host -B build/semi_slam_host && cmake --build build/semi_slam_host -j4 && ctest --test-dir build/semi_slam_host
```

`slam_test`는 거리·자이로 오차를 넣은 모의 주행으로 바퀴 세기, 보정 값 복원·누적, 위치 추정 오차, BEV 회전 검산, 정지선 기울기 측정을 확인한다.
웹 화면만 볼 때: `web/index.html?demo`.
