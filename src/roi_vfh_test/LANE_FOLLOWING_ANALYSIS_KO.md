# VFH 중앙선 추종이 약하게 보이는 경로 (2026-11-10)

소스 분석이다. 새 실차 로그나 녹화 자료로 각 원인의 발생 빈도를 확인하지 않았고,
사용자 요청대로 빌드·테스트·실차 실행은 하지 않았다. 이 변경에서 추종 가중치와
센서 만료/동기화 제한을 조정하지 않았다.

## 1. 현재 중앙선이 보여도 추종 입력으로 채택되지 않을 수 있다

`LaneMemory::resolve`는 기본 0.8초 동안 연속 관측, 길이 0.4m 이상,
위치 일관성 0.15m, 방향 일관성 12도 조건을 요구한다. 관측 간격이 0.15초를
넘으면 확인 시간을 다시 시작한다. 유효 경로가 없는 호출은 pending 형상을 지운다.

`preview_node.cpp`는 현재 차선이 미신뢰이고 저장된 중앙선도 없으면
`working.avoidance_lane_weight=0`으로 강제한다. 이때 실제 계획 기준선은
전방 직선이다. 따라서 화면에서 차선을 검출했더라도 `Lane: confirming`과
`Lane memory: no` 상태에서는 차선 가중치를 높여도 현재 차선으로 복귀하지 않는다.

이번에 추가한 `lane_memory_enabled=0.0`은 과거 중앙선 저장/복원을 끈다.
연속 검증을 생략하는 옵션은 아니다. 현재 관측이 검증을 통과하면 직접 추종하며,
통과하지 못하면 저장된 기준선 없이 전방 선호로 VFH를 사용한다.

## 2. 최신 지형 우선 선택과 60ms 동기화 제한의 상호작용

현재 기본 launch의 `max_sync_sec`는 ROI 0.08초와 avoidance 0.06초 중
작은 값인 0.06초다. 차선 자체는 0.30초 이내여도, 선택한 terrain 촬영 시각과
60ms 넘게 다르면 `paired_lane`에서 제외한다. 이동 이력이 해당 촬영 자세를
포함하지 않는 경우에도 제외한다.

e2d746e에서 지형 만료를 줄이려고 선택 순서를 최신 terrain 우선으로 변경했다.
이 변경은 추론이 늦는 경우 이전의 차선 근접 terrain 선택보다 차선 누락을 늘릴 수 있다.
누락이 1번의 연속 확인을 초기화하면, 검출은 되는데 신뢰에 도달하지 못하는 상태가
반복될 수 있다. 이는 코드상 가능한 경로이며 현장의 실제 촬영 시각 차이는 미확인이다.

현재 신뢰된 중앙선이 없을 때 과거 중앙선만 기억해 두는 것도 별도 원인이다.
새 차선이 검증되지 않으면 ON 상태에서는 이전 형상과 그 끝의 접선 연장이 기준이 된다.
저장된 형상에는 시간 만료가 없으므로 오래된 기준을 따르는 것처럼 보일 수 있다.

## 3. 차선을 채택한 뒤에도 회피 후보는 차선 우선순위가 절대적이지 않다

충돌 없는 현재 차선 추종 궤적은 Stanley 제어를 사용해 VFH를 우회한다.
이때 직접적인 횡방향 보정 계수는 `stanley_gain`(기본 1.3)이다.

VFH 경로에서는 가장 긴 후보보다 0.40m 넘게 짧은 후보를 먼저 제외한다.
남은 후보 점수는 길이 손실, 장애물 여유, 전진량, 조향 연속성, 차선 비용을 합산한다.
차선 비용 계수는 `0.6 * avoidance_lane_weight`이고 기본값은 0.48이다.
가중치를 높여도 길이 비교 단계에서 제외된 차선 근접 후보는 선택되지 않는다.

## 개선 우선순위

1. 현재 차선이 신뢰되지 않는 원인을 구분한다: 검출 무효/경로 짧음/시각 차이/이동 이력 부족.
2. 최신 지형은 유지하면서, 유효한 차선을 각 촬영 자세로 독립 보정해 쓸 수 있는지 검토한다.
   동기화 제한을 단순히 늘리거나 오래된 입력을 새것으로 취급하는 변경은 하지 않았다.
3. 채택되는 현재 차선이 충분할 때 회피 복귀에는 `avoidance_lane_weight`, 직접 추종에는
   `stanley_gain`을 각각 조정한다. 두 계수는 적용되는 경로가 다르다.

이번 구현 범위는 장애물 위치 기억 제거와 차선 기억 ON/OFF 추가다.
위 추종 정책 변경은 분석 및 후속 검토 항목으로 남겼다.
