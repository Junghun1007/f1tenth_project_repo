# 실차 공통 VFH+ 로컬 시뮬레이터

실차 `roi_vfh_test`의 경로 판단을 정상 센서 입력·이상적인 위치 추정 조건에서 검토한다.
사용자 결정에 따라 속도 응답은 기존 가감속 차량 모델을 유지한다.

## 실행

저장소 루트에서 Python 3와 C++17 컴파일러로 실행한다. ROS·PyYAML 설치는 필요 없다.

```bash
python3 src/auto_control/tools/vfh_sim/serve.py --port 8785 --planner vfh \
  --scene src/auto_control/tools/vfh_sim/scenes/default.json
```

서버 시작 시 최신 실차 공통 헤더로 C++ worker를 컴파일한다. 브라우저는 출력된 주소를 연다.
서버 실행 중 정책/설정 파일이 바뀌면 화면에 재시작 필요 상태를 표시한다. 다른 빌드의
페이지에서 요청하면 버전 불일치를 알린다. 배치를 JSON으로 보관한 뒤 서버 재시작/페이지
새로고침을 수행한다. 자동으로 장면이나 마킹을 버리지 않는다.

## 설정의 기준

`vehicle_profile.py`가 실차 launch에서 사용하는 다음 파일의 scalar 설정을 읽는다.

- `src/roi_vfh_test/config/preview.yaml`
- `src/roi_vfh_test/config/reference/{auto_control,obstacles,camera_config,bev_config,line_detactor,roi_lidar}_test.yaml`
- 누락 ROI 기본값은 `src/roi_lidar/config/roi_lidar.yaml`에서 가져온다.

`--params-file`, `--reference-dir`로 다른 실차 프로필을 선택할 수 있다.
필요한 수치/불리언 항목이 없거나 scalar 형식이 아니면 실행을 거부한다. YAML anchor/alias 등
복합 문법은 이 설정 로더에서 지원하지 않는다. 별도 라이브러리를 임의로 설치하지 않는다.

서버가 UI 기본값과 C++ 고정 설정 헤더를 같은 프로필에서 생성한다. 기본 장면은 장애물·마킹
배치를 보존하면서 실차 기본 설정을 적용한다. 사용자 JSON의 명시적 튜닝 값은 가져오기에서
유지한다. ‘기본값 복원’은 현재 실차 프로필을 사용하며 장애물·마킹은 유지한다.
속도·감속도·조향각·조향 변화율의 실차 상한과 VFH 입력 검증을 적용한다.

## 공유하는 정책

실차 파일을 직접 포함한다.

- `planner.hpp`: 차선 직접 추종, VFH+ 히스토그램, 추가 곡선, 차체·패딩 검사, 후보 점수/속도 제한.
- `policy_state.hpp`: 차선 유실 시 마지막 방향 기억. ON/OFF도 같은 입력으로 전달한다.
- `hazard_filter.hpp`: 작은 hazard의 연속 관측 확인과 자차 이동 보정.
- `obstacle_memory.hpp`: 확정 장애물의 깜빡임 유지·근거리 측면/후미 기억 및 해제.
- `speed_policy.hpp`: 장애물 감속 유지와 목표 속도 회복 제한. ROS와 시뮬레이터가 같은 함수를 호출한다.
- `auto_control/control_core.cpp`: Stanley 등 공통 제어 기하.

유도 통로를 별도로 분류하거나 차선 이탈 거리를 제한하지 않는다. 회색 미관측 셀과
격자 바깥은 통과 가능으로 취급한다. 확정 관측했던 위험 셀은 실차와 같은 짧은 기억을 사용해
측면·후미까지 검사한다. 녹색 재관측·후미 통과·최대 수명에 따라 해제하며 자유 영역 지도는 누적하지 않는다.
차선이 있으면 그 형상을 우선하고, 없으면 마지막 방향 또는 차량 전방을 선호하며 회피한다.

## 독립된 관측·계획·구동 시계

현재 실차 기본 프로필은 RGB/차선 80Hz, Depth/terrain 40Hz, 계획 80Hz, 구동 100Hz다.
주기는 YAML에서 읽고, 시뮬레이션 시간의 해당 시점마다 이벤트를 처리한다.

- 관측은 그때의 차량 자세로 캡처한다. 한 Depth가 여러 계획 호출에서 재사용될 수 있다.
- 새로운 차선과 최신 terrain의 촬영 자세가 다르면 공통 `reproject`로 좌표를 맞춘다.
- 계획 주기를 낮춰도 사이에 들어온 Depth를 버리지 않는다. blank 관측을 포함해 시간순으로
  필터에 전달한다. 같은 Depth를 여러 번 확인한 것으로 세지 않는다.
- 같은 차선/terrain 촬영 쌍이면 계획 결과를 재사용한다. 차선 유실/복구는 새 판단으로 처리한다.
- `입력 나이 + 계획 1주기`와 사용자 반응 지연 중 큰 값을 사용한다.
- 100Hz 구동은 실차의 조향 필터·조향각/변화율 제한을 적용한다. 목표 0에서는 조향을 유지한다.
- 물리 속도는 기존 가감속 모델을 따른다. VESC Duty·브레이크 전류·모터 모델은 모사하지 않는다.
- 물리 적분은 이벤트 사이를 최대 5ms로 나누고 실제 차체와 장애물의 충돌을 평가한다.

주행 전 설정을 적용하고 주행 중에는 잠근다. 차선 관측 체크는 정상적인 ‘빈 차선 인식 결과’를
만드는 실험 입력이다. 입력 누락이나 통신 장애를 주입하는 스위치는 추가하지 않는다.

## 센서와 평가의 한계

장애물 raycast는 관측 모사에서만 전체 배치를 참조한다. C++ 계획기에는 관측된 위험 셀과
차선 점만 전달한다. 실제 DepthAI/RANSAC·신경망 잡음·자세 추정 오차는 모사하지 않는다.
속도/IMU/통신은 정상이며 정확한 시뮬레이터 자세를 사용할 수 있다고 가정한다. 따라서 실차
센서 유실·입력 대기·0.5초 재출발 복구를 검증하는 장면은 이번 범위에 포함하지 않는다.

마킹 좌표·크기·순서는 계획기 프로토콜에 포함하지 않는다. 마킹은 움직임 이후 통과 여부와
순서만 평가한다. 전체 트랙과 장애물 정답 정보도 목표나 경로 점수로 넘기지 않는다.

## 계산 시간

C++ 계획·hazard 필터 시간은 worker 내부에서 측정한다. 관측 모사·로컬 요청 시간은 따로
기록한다. Jetson 배율은 임의 추정이며 실제 기기 측정값이 아니다. 이번 수정에서는 주행
테스트를 실행하지 않았다. 실행 화면 갱신을 위한 C++ 컴파일과 소스 검토만 수행한다.

## 장애물 깜빡임·측면/후미 기억 설정

실차와 같은 `hazard_hold_sec=0.30`, `obstacle_memory_enabled=1`,
`obstacle_memory_sec=2.0`, `obstacle_memory_distance_m=1.0`,
`obstacle_memory_clearance_m=0.10`을 기본으로 읽는다. 차체 주변 기억 거리는 차체 표면부터다.
최대 기억시간을 넘으면 통과 전에도 해제되므로 낮은 속도에서는 이 값을 함께 조절한다.
다섯 값과 기존 `obstacle_uncertainty_m`을 출발 전 설정에서 편집하고 주행 중에는 잠근다.
BEV는 기억 셀과 후미를 포함하는 확장 격자 원점을 표시한다. 주황은 유지·기억 위험,
빨강은 현재 위험 관측이며 둘 다 충돌 검사 대상이다. 마킹은 계속 평가에만 사용한다.
수정 후 주행/회귀 테스트는 실행하지 않았다.

## 가속·조향 튜닝

실차 편집기와 같은 목표 속도 회복 가속도·최대 조향각·조향 변화율·새 조향 명령 가중치·
Stanley 계수/저속 완화/코너 보정·최대 곡률을 출발 전에 편집할 수 있다. 도 단위 UI와
라디안 공통 코어를 변환하며 실제 차량 프로필의 조향 상한을 브라우저와 worker가 모두 검사한다.
차량 모델 가속도는 물리 모사 값이고 목표 회복 가속도는 계획 속도 제한이므로 따로 표시한다.
실차 전용 Duty/브레이크 전류 튜닝은 모터 모델이 없는 이 시뮬레이터에 노출하지 않는다.
