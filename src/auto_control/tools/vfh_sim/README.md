# 프레넷·VFH 로컬 주행 시뮬레이터

기본 실행은 `python3 serve.py`이며 VFH+ 계획기를 사용한다.
프레넷 실험은 `python3 serve.py --planner frenet`으로 실행한다.
두 계획기를 동시에 비교할 때는 `--port`로 포트를 구분한다.

프레넷은 차선 기준 진행 거리와 좌우 오프셋으로 목표 궤적을 만들고,
조향·조향 속도 제한을 적용한 차체 궤적으로 검증한다.
콘 유도 미션 상태를 따로 판정하지 않는다. 일반 차선 추종 궤적이 열려 있으면 기존
Stanley 추종을 쓰고, 막혔을 때 프레넷 후보를 비교한다. ROS 실차 실행 경로는 별도다.


저장소 루트에서 다음 명령으로 실행한다. Python 3와 C++17 컴파일러가 필요하다.

```sh
cd src/auto_control/tools/vfh_sim
python3 serve.py --port 8772
```

브라우저에서 http://127.0.0.1:8772/ 를 연다. 소스 변경 후 서버를 재시작한다.
서버는 roi_vfh_test/include/roi_vfh_test/planner.hpp와 policy_state.hpp,
기존 ROS HazardFilter 및 auto_control의 Stanley 제어 코어를 빌드한다.
계획·차선 신뢰도/기억 정책은 실차와 같은 소스다. 네이티브 장애물 위치 기억은 제거했다.
실차는 ROS 센서 촬영 정렬과 VESC PID/제동 어댑터를 사용하며, 이 시뮬레이터는
이상적인 위치·센서와 차량 적분을 사용하므로 실제 주행 결과까지 같다는 의미는 아니다.

## 주행 정책

- 신뢰할 수 있는 현재 차선의 추종 궤적이 비어 있으면 차선 추종을 사용한다.
- 장애물이 추종 궤적을 막거나 현재 차선이 신뢰도 검사에 통과하지 않으면 VFH 후보를 검사한다.
- 차선까지의 거리는 회피 후보의 복귀 선호에 반영한다. 충돌이 없는 후보를 차선 이탈 거리로 잘라내지 않는다.
- 모든 후보를 현재 위험 셀과 비교해 차체·패딩 충돌을 검사한다. 장애물 위치를 누적하지 않는다.
- 후보 진행 길이를 우선하고 길이 비교 여유 안에서 장애물 여유, 조향 연속성, 차선 복귀 선호를 비교한다.
- 차선은 일정 시간 연속 검출되고 길이·위치·방향 일관성 조건을 통과해야 기억을 갱신한다.
- 신뢰한 차선 경로를 월드 좌표로 기억하고 차량 이동에 맞춰 현재 좌표로 변환한다.
- 차선을 놓치면 마지막으로 신뢰한 중앙선을 새 중앙선이 확인될 때까지 복귀 기준으로 사용한다.
- 기억 경로 끝을 지나면 마지막 접선 방향으로 연장해 복귀 선호를 계산한다. 관측되지 않은 연장 구간은 가정이다.
- 새 차선도 신뢰도 검사를 통과하고 차체 궤적이 충돌 없이 연결돼야 직접 추종으로 복귀한다.
- 통과 가능한 전진 후보가 없으면 정지한다. 미관측 셀과 격자 밖은 통과 가능으로 가정한다.


## 조작과 확인

- 주행 시작·일시정지, 0.1초 진행, 차량 초기화 버튼을 사용한다.
- 차선 관측 체크박스는 주행 상태를 유지하며 유실·재관측을 시험한다.
- 보이는 차선 길이 입력도 즉시 적용된다. 0.2m로 줄여 짧은 조각의 기억 갱신 거부를 확인할 수 있다.
- 나머지 설정은 적용 버튼으로 반영하며 차량을 초기화한다.
- 원·사각형을 추가하거나 이동하고 촘촘한 콘 배열을 드래그로 그릴 수 있다.
- VFH+의 편집 도구에서 **통과 영역 추가**를 선택하고 지도에 클릭한다. 원 지름 기본값은 0.20m다.
  번호 순서대로 앞차축 중심이 원 안에 들어오면 통과로 기록한다. 마킹은 평가 전용이며 좌표·순서·통과 사건을 계획기에 전달하지 않는다.
  선택·이동으로 위치와 지름을 바꿀 수 있다. 미통과 영역이 있으면 완주로 집계하지 않는다.
- 장면·설정 JSON으로 장애물, 통과 영역, 설정을 저장·복원한다. 불러온 명시 설정은 기본값보다 우선한다.
- 상태에는 missing / too short / confirming / trusted를 표시한다.
- Mac 처리 시간에는 C++ 계획·hazard 확인·센서 모사·통신 포함 처리 시간을 표시한다.

장애물은 가장 가까운 광선 관측만 terrain으로 변환한다. C++ 계획기는 원본 객체 목록을 받지 않는다.
차선은 이상적인 직선에서 합성하고 차량 위치·속도·yaw·조향이 제공된다고 가정한다.
실제 depth 처리·차선 신경망·센서 동기화·VESC 구동은 모사하지 않는다.
전체 유도 통로 완주와 실제 차량의 통과 가능성을 보장하는 실험은 아니다.


## 도면 순환 트랙 프리셋

장면 메뉴의 도면 순환 트랙은 제공된 도면의 비율과 격자를 참고해 외곽 13×4m,
차선 안쪽 폭 0.65m, 중앙선 모서리 반경 0.5m로 근사했다. 실측 도면의 확정 치수가 아니다.
오른쪽 아래 출발점에서 오른쪽으로 출발하고, 오른쪽 곡선 → 상단 왼쪽 방향 →
왼쪽 곡선 → 하단 오른쪽 방향으로 한 바퀴 약 29.14m를 주행한다.
지그재그 콘 8개, 두 줄 유도 콘 38개만 배치한다.
차선 경계는 인식용 기하이며 물리적 벽으로 처리하지 않는다.
중앙선 가까이 출발점으로 돌아온 진행량을 기준으로 한 바퀴 종료를 판정한다.

기존 직선 프리셋을 선택하면 직선 코스로 돌아간다. 사용자 배치는 현재 코스 형상을 유지한다.
원형·사각형 추가 도구로 지도 클릭, 촘촘한 콘 배열 도구로 드래그, 선택·이동 도구로
장애물 이동을 지원한다. 선택 장애물의 X/Y 위치와 크기를 숫자로도 편집할 수 있다.
순환 트랙의 편집 범위는 X=0~13m, Y=0~4m이며 JSON 저장·복원에도 코스 형상을 포함한다.


추가 상세 도면에 따라 테이프 폭 3cm, 테이프 중심 간격 68cm, 안쪽 빈 폭 65cm,
바깥 폭 71cm로 표시한다. 코너의 안/바깥 테이프 중심 반경은 16/84cm다.
콘 바닥은 13×13cm 사각형이다. 1단계는 진행 거리 25/75/125/175cm에서
좌/우/좌/우로 두 개씩 붙여 배치한다. 바깥 콘 중심을 테이프 중심에 놓고
안쪽 콘을 13cm 붙여 차선 안쪽 끝에서 18cm 돌출하고 47cm를 남긴다.

2단계 중심선은 3m 구간에서 y=0.34*(1-cos(2*pi*x/3))m로 정한다.
중앙선에 수직인 방향으로 각각 34cm 떨어진 두 줄에 19개씩, 총 38개를 배치한다.
중심선 호 길이를 18등분해 약 18.6cm 간격으로 배치하며, 중앙에서 68cm 이동한 뒤 복귀한다.
콘 바닥의 회전각은 현재 편집기의 축 정렬 사각형 모델을 사용한다.


순환 트랙의 VFH 기본값은 목표 속도 0.75m/s, 계획 거리 1.00m, 회피 목표 거리 1.20m,
terrain 셀 0.025m, 곡선 샘플 13개, 길이 비교 여유 0.10m, 차체 패딩 0.01m다.
복귀, 조향 연속성, 장애물 여유 가중치는 각각 1.8, 1.0, 4.0이다.
기존 장면에서 주행·차량·VFH 설정의 검증된 순환 트랙 설정 적용 버튼을 누르면 배치를 유지하고 이 설정으로 차량을 초기화한다.
전장 50cm는 앞차축 기준 앞 5cm와 뒤 45cm로 나눈 값이다.
C++ 계획기는 개별 장애물과 콘 배열을 동일한 격자 입력으로 처리한다.

## 평가용 마킹과 프리셋 비교 (2026-11-09)

마킹은 평가 전용이다. core.js의 독립 평가기가 순차 통과만 기록한다.
VFH 프로토콜과 C++ 계획기는 마킹 좌표·크기·순서를 받지 않으며,
마킹을 통과해도 재계획 시각이 바뀌지 않는다. 마킹 위치를 옮기거나
추가·삭제·크기 변경·순서 변경해도 같은 센서와 설정에서 경로는 동일하다.
화면은 평가된 통과 개수와 한 바퀴 종료 시 미통과 영역을 표시한다.

기존 프리셋 목록과 트랙 전용 파라미터 덮어쓰기를 제거했다.
native.js의 기본값 한 벌을 사용하며, ‘기본값 복원’은 장애물과 마킹을 유지하고
주행·차량·VFH 파라미터를 기본값으로 되돌린다. 차선 밖 거리는 제한하지 않고
충돌 없는 후보 중 마지막으로 신뢰한 중앙선 쪽 복귀를 선호한다.
조정 전·이전 튜닝 파일과 70회 비교 결과는 과거 실험 기록으로만 보존했다.
비교 도구도 UI 프리셋 대신 기록에 저장된 설정을 사용한다.

```sh
python3 serve.py --port 8785 --scene scenes/default.json
node marker-evaluation-smoke.cjs
node compare-evaluation-presets.cjs
```

비교는 동일한 7개 배치 × 5개 목표 속도(0.5/0.7/0.85/1.0/1.2m/s)를
두 프리셋에 적용한다. 속도만 공통 값으로 덮어쓰고 나머지 파라미터는 고정한다.
사용자 배치, 5mm/2cm/5cm 좌표 흔들림, 소수 장애물 진행 방향 ±20cm 이동,
빈 트랙 대조군을 사용한다. 빈 트랙에서는 평가 마킹도 차선 위로 투영한다.
나머지 여섯 배치는 사용자가 지정한 마킹 위치·크기·순서를 그대로 유지한다.
평가용 전체 객체 목록은 독립 충돌 검사와 결과 집계에만 사용하며,
계획기에는 광선 관측으로 만든 terrain과 차선 관측만 제공한다.

0.01초마다 실제 차체 충돌을 검사한다. 한 바퀴와 전체 차체 차선 복귀를
만족한 비율과, 이에 더해 모든 마킹을 순서대로 통과한 비율을 따로 집계한다.
마킹을 놓쳐도 실험을 조기 종료하지 않는다. 평가 시간은 최대 140초이며
목표·실제 속도 0.01m/s 미만이 3초 지속되면 정지로 분류한다.
시험 범위 x[-5,18], y[-5,9] 밖에서 실험을 종료하는 것은 평가 예산이며
제어기나 회피 경로에 차선 이탈 한도를 추가한 것이 아니다.

계획기의 선택 길이·최장 후보 길이·hazard로 잘린 후보 수·짧은 후보 수·차선 신뢰도와
마지막 20개 계획, 충돌 대상과 제동 중 여부도 기록한다.
수치 결과는 evaluation-comparison-results.json, 설명은
EVALUATION_COMPARISON_KO.md, 재현 배치는 evaluation-comparison-results-scenes/에 저장한다.
이것은 한 트랙의 고정된 변형 비교이며 무작위 독립 표본의 성공 확률이나 실차 검증이 아니다.

## 현재 단일 기본 설정

사용자 요청으로 파라미터 실험의 C 설정(36.22초 한 바퀴)을 기본값으로 적용했다.

목표 속도 1.00m/s, 계획 거리 1.20m, 회피 목표 거리 1.00m,
차체 패딩 0.02m, terrain 셀 0.025m, 곡선 샘플 17,
길이 비교 여유 0.40m, 차선 복귀/조향 연속성/장애물 여유 가중치 0.8/0.1/1.0.
경로 검사 간격 0.03m, 차선 lookahead 0.05m와 나머지 차량·센서 값은 유지했다.
차선 이탈 거리에 대한 강제 제한은 없다. 통로 분류기는 없고 마킹은 평가 전용이다.

이전 실험 결과 파일은 측정 당시 설정과 결론을 그대로 보존했다.

## ROS 공유 정책 이식 (2026-11-09)

사용자 결정에 따라 ROI VFH는 앞차축 기준 앞 5cm/뒤 45cm, terrain 2.5cm로 통일했다.
기억 장애물·패딩 겹침에 의한 정지 증상도 개선하지 않고 현재 의미 그대로 공유한다.
정책 소스는 roi_vfh_test 패키지에 한 벌만 있으며 시뮬레이터의 policy_include 헤더는
그 소스로 연결하는 호환 파일이다. 같은 촬영 결과의 중복 사용은 차선 신뢰 시간을 늘리지 않는다.
실차 UI에는 이탈 한도 대신 여유 가중치와 4개 차선 신뢰도 항목이 표시된다.
마킹·실험용 단면·트랙 원본 객체는 실차에 전달하지 않는다.
이번 공유 코드 이식에서는 사용자 요청대로 빌드·테스트·시뮬레이터 재실행을 하지 않았다.
