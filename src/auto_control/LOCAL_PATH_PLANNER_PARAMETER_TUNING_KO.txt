0830ver1 로컬 경로·아웃-인-아웃·공간 속도 프로파일 파라미터 가이드
=======================================================================

1. 구조와 안전 원칙
-------------------

- bev_processor는 mono8 중앙선 외에 순서가 보존된 nav_msgs/Path 3개를 발행한다.
  /camera/path_bev_lane       : 차선 기준 중앙선
  /camera/path_bev_lane_left  : 실제 검출 왼쪽 경계
  /camera/path_bev_lane_right : 실제 검출 오른쪽 경계
- auto_control은 좌우 경계의 곡률이 같다고 가정하지 않는다. 중앙선 각 지점에서
  양쪽 경계까지 최단거리를 각각 측정해 주행 가능 corridor를 만든다.
- /auto/planned_path가 실제 Stanley 추종 경로이다. RViz의 Path 표시로 확인한다.
- 새 경로를 시험할 때 bev_processor의 lane_centerline_corner_outward_bias_m은
  0.0으로 둔다. 둘 다 켜면 코너 오프셋이 중복된다.
- 처음에는 electrical_brake_enabled=false, 낮은 속도, 바퀴를 띄운 dry-run으로
  경로 부호를 확인한다. 이후 racing_line_weight를 작은 값부터 올린다.

2. 실차에서 반드시 측정해 입력할 값
-------------------------------------

local_path_vehicle_width_m
  타이어 바깥쪽에서 반대쪽 타이어 바깥쪽까지의 최대 폭. 차체가 더 넓으면 차체
  최대 폭을 사용한다. 기본 0.30m는 임시값이며 줄자로 실제 값을 측정한다.

local_path_vehicle_wheelbase_m
  앞차축 중심과 뒤차축 중심 사이 거리. 기본 0.324m는 임시값이다. 최대 조향각과
  함께 기구학적 최대 곡률 tan(max_steering)/wheelbase를 제한하는 데 사용한다.

local_path_expected_lane_width_m
  직선 여러 곳에서 좌우 차선 안쪽 경계 사이를 측정한 중앙값. 현재 0.65m.
  한쪽 차선만 보일 때의 대체 폭이므로 실제 트랙 폭 중앙값을 입력한다.

local_path_safety_margin_m
  차량 측면과 차선 사이에 추가로 남길 거리. 권장 시작값은
  횡오차 95 percentile + BEV 오차이다. 횡오차가 최대 0.10m이면 0.10~0.12m부터
  시작하고, 안정화 후 0.01m씩 줄인다. 현재 0.08m는 저속 시험용이다.

3. 실행 방법
------------

각 노드 YAML 파일을 따로 전달하는 기존 방식은 그대로 지원한다.

ros2 launch vehicle_bringup auto_drive.launch.py \
  bev_params_file:=/home/autopilot03/Desktop/0822ver3/f1tenth_project_repo/bev_config_test.yaml \
  auto_control_params_file:=/home/autopilot03/Desktop/0822ver3/f1tenth_project_repo/auto_control_test.yaml

YAML 값을 일시적으로 덮어쓸 수도 있다.

ros2 launch vehicle_bringup auto_drive.launch.py \
  bev_params_file:=/path/bev_test.yaml \
  auto_control_params_file:=/path/auto_test.yaml \
  local_path_racing_line_weight:=0.30 \
  local_path_safety_margin_m:=0.10 \
  spatial_speed_profile_enabled:=true \
  speed_profile_maximum_longitudinal_deceleration_mps2:=1.2

이전 방식 비교:
  path_input_mode:=image         mono8 행 평균 경로
  path_input_mode:=ordered_path  순서 보존 Path + corridor planner (권장)

4. Corridor 폭 파라미터
----------------------

local_path_minimum_half_width_m: 0.24
  이보다 좁게 측정된 방향으로는 선택적 아웃-인-아웃 이동을 하지 않는다.
  실측값을 이 값까지 인위적으로 넓히지는 않는다. 차량 반폭+안전여유보다 크게,
  실측 정상 최소 반폭보다는 작게 둔다.

local_path_maximum_half_width_m: 0.48
  반사광이나 잘못된 경계를 폭으로 받아들이지 않도록 하는 상한. 실측 최대 반폭에
  5~10cm를 더한 값으로 시작한다.

local_path_width_smoothing_window_m: 0.20
  진행거리 방향 폭 중앙값 필터 길이. 폭이 출렁이면 0.25~0.35m로 증가한다.
  실제로 폭이 빠르게 변하는 구간 반영이 늦으면 0.12~0.18m로 감소한다.

local_path_maximum_center_correction_m: 0.08
  양쪽 경계가 동시에 실측된 구간에서, 기존 BEV 중앙선을 실제 corridor
  중앙으로 바로잡는 최대 거리다. 기존 중앙선의 양쪽 경계 거리 차이의
  절반을 로그에서 관찰해 정한다. 너무 크면 잘못된 경계에 따라 경로가
  튀므로 0.08~0.15m로 시작한다. 0.0은 중앙 보정을 끄는 값이다.

local_path_resample_interval_m: 0.02
  경로 점 간격. 0.02m는 2cm이다. 작을수록 부드럽지만 CPU 사용과 노이즈 민감도가
  증가한다. 일반 범위 0.015~0.04m.

5. 코너 검출 파라미터
---------------------

local_path_corner_curvature_threshold_per_m: 0.45
  이 곡률 이상을 코너 후보로 본다. 반지름 기준 R=1/curvature이므로 0.45는 약
  2.22m 반지름이다. 직선 요철을 코너로 오인하면 값을 높이고, 완만한 코너를
  놓치면 낮춘다. 0.35~0.80 범위에서 조정한다.

local_path_corner_curvature_smoothing_window_m: 0.16
  코너 판정용 곡률 평활 길이. 코너 상태가 깜빡이면 증가, 코너 진입/탈출이 늦으면
  감소한다. 일반 범위 0.10~0.25m.

local_path_corner_minimum_heading_change_deg: 20.0
  후보 구간의 누적 방향 변화가 이 값보다 작으면 코너로 인정하지 않는다.
  직선 요철 오검출 시 25~35도, 코너 누락 시 12~18도로 조정한다.

6. 아웃-인-아웃 파라미터
------------------------

local_path_corner_approach_length_m: 0.35
  코너 시작 전부터 바깥쪽으로 이동하는 거리. 조향이 늦으면 증가하고, 코너를 너무
  일찍 돌아 차선을 밟으면 감소한다. 현재 카메라 시야와 속도에서 0.25~0.60m 권장.

local_path_corner_exit_length_m: 0.40
  코너 종료 후 바깥쪽에서 기준 중앙으로 복귀하는 거리. 탈출 조향이 급하면 증가,
  다음 코너 대응이 늦으면 감소한다.

local_path_outside_offset_fraction: 0.25
  진입/탈출에서 사용할 수 있는 측면 여유 중 몇 %를 바깥쪽으로 사용할지 결정한다.
  처음 0.20~0.30으로 시험하고 최대 0.50 정도까지만 단계적으로 올린다.

local_path_apex_offset_fraction: 0.35
  apex에서 사용할 수 있는 안쪽 여유의 비율. 안쪽 차선을 밟으면 즉시 낮추거나
  safety_margin을 높인다. 저속 시작 권장값 0.30~0.45.

local_path_maximum_offset_m: 0.08
  어떤 경우에도 기준 중앙선에서 이동할 수 있는 절대 한계. 사용 가능한 corridor가
  더 좁으면 자동으로 그보다 작아진다. 트랙 반폭에서 차량 반폭과 안전 여유를 뺀
  값보다 작아야 한다.

local_path_maximum_offset_slope: 0.70
  진행거리 1m당 횡오프셋 최대 변화량. 경로가 좌우로 급변하면 0.4~0.6으로 낮추고,
  급코너 apex에 못 붙으면 0.8 정도까지 올린다.

local_path_racing_line_weight: 0.20
  계산된 아웃-인-아웃 오프셋 적용 비율. 0이면 기존 중앙선, 1이면 전부 적용한다.
  필수 시험 순서: 0.0 -> 0.2 -> 0.4 -> 0.6. 횡오차와 차선 여유를 확인한 뒤 올린다.

local_path_maximum_curvature_per_m: 1.8
  선택 경로의 목표 곡률 한계. 실제 적용값은 이 값과
  tan(maximum_steering_angle)/wheelbase 중 작은 값이다. 기준 중앙선 자체가 한계를
  넘으면 트랙을 따라가기 위해 기준 곡률은 허용하지만 선택 오프셋이 더 악화시키지
  않도록 자동 축소한다.

7. 공간 속도·트레일 브레이킹형 프로파일
----------------------------------------

spatial_speed_profile_enabled: true
  false면 기존 curvature percentile 단일 목표속도를 사용한다.

speed_profile_lookahead_minimum_s_m: 0.05
speed_profile_lookahead_maximum_s_m: 2.80
  현재 경로의 진행거리 s 기준 검사 범위. 최대값은 실제 안정적으로 검출되는 경로
  길이보다 작게 둔다. 경로가 1.5m뿐이면 2.8m를 줘도 실제 경로 끝까지만 사용한다.

speed_profile_sample_interval_m: 0.04
  속도 프로파일 계산 간격. 0.03~0.08m 권장.

speed_profile_maximum_longitudinal_deceleration_mps2: 1.8
  backward pass가 가정하는 최대 감속. 실제보다 크게 입력하면 감속 시작이 늦어진다.
  주행 로그에서 안전하게 재현되는 실제 감속도의 70~80%부터 사용한다.

speed_profile_maximum_longitudinal_acceleration_mps2: 1.2
  코너 탈출 후 목표속도 증가 한계. 탈출 가속이 급하면 낮추고, 지나치게 느리면
  실제 가속 성능 이하에서 조금씩 올린다.

speed_profile_minimum_combined_braking_ratio: 0.20
  횡가속이 한계에 가까운 apex에서도 남겨 둘 종감속 비율. 실제 트레일 브레이킹처럼
  apex에서 제동을 많이 풀려면 0.10~0.20, 저속 안전 우선이면 0.25~0.40.

speed_profile_acceleration_control_distance_m: 0.20
  현재 속도에서 목표속도를 올릴 때 한 번에 허용할 공간적 가속 거리. 가속 목표가
  급변하면 감소, 탈출이 너무 굼뜨면 증가한다.

maximum_lateral_acceleration_mps2
  기존 값이 곡률별 제한속도를 결정한다: v=sqrt(a_lat/|curvature|).
  실제 횡가속 한계를 모르면 0.6~0.9m/s^2로 시작해 로그를 보며 올린다.

electrical_brake_enabled
  공간 프로파일은 목표속도만 생성한다. true일 때만 목표보다 빠른 실제 속도에
  전기적 브레이크를 사용한다. 처음에는 false로 경로를 검증하고, 감속 시작 위치가
  맞는 것을 확인한 뒤 낮은 brake current부터 켠다.

8. 권장 필수 시험 순서
----------------------

1) 차량 정지/dry-run: /auto/planned_path를 RViz로 보고 좌회전은
   바깥 오른쪽 -> apex 왼쪽 -> 탈출 오른쪽인지 확인한다. 우회전은 반대다.
2) local_path_racing_line_weight=0.0, spatial_speed_profile_enabled=false로
   ordered Path가 기존 중앙선 주행과 같은 방향인지 확인한다.
3) weight=0.2, minimum speed로 차선 여유와 횡오차를 기록한다.
4) weight를 0.1~0.2씩 증가한다. apex_offset보다 safety_margin을 먼저 확정한다.
5) spatial_speed_profile_enabled=true, electrical_brake_enabled=false로 duty 감소
   시점을 확인한다.
6) 마지막에 electrical_brake_enabled=true와 낮은 brake current를 적용한다.
