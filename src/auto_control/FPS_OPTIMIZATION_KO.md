# auto_control FPS·연산 최적화

## 적용 범위

차선 추종/회피 방식, 차체·패딩, 차선 복귀 선호, 충돌 판정, 감속·정지 기준과
입력 최대 수명, 정상 FPS 설정은 유지한다. 잘못된 중복 판정을 고치고 계산·표시
작업의 반복을 줄인다. 실제 성능 향상률은 이번 작업에서 측정하지 않았다.

## 1. 입력 유실 시 발행 폭주 방지

- 회피 worker의 정상/오류/OFF 처리 모두 `obstacles.avoidance.max_fps` 간격으로 실행한다.
- 1ms 반복 polling을 다음 실행 시각까지의 condition-variable 대기로 바꾼다.
- 설정 변경과 종료는 대기를 깨운다. 설정 변경 시 새 설정을 즉시 반영한다.
- 오류를 처음 확인하면 그 회차에 무효 계획을 보낸다. 같은 오류의 무효 계획도
  계획 FPS 상한 안에서 재발행해 best-effort 통신의 유실에 대비한다.
- 같은 상태 문자열은 1Hz heartbeat, 상태 변화는 바로 발행한다.
- 같은 오류에서 planner 무효화/프리뷰 삭제를 반복하지 않는다. 제어기 watchdog은 그대로다.

## 2. 차선·Depth 입력 쌍 판정 통일

공유 `capture_pair_order.hpp`를 생산자와 제어기에서 사용한다.

| 이전 입력에 대한 새 입력 | 처리 |
|---|---|
| 같은 차선 + 새 Depth | 새 계획 허용 |
| 새 차선 + 같은 Depth | 새 계획 허용 |
| 새 차선 + 새 Depth | 새 계획 허용 |
| 같은 차선 + 같은 Depth | 중복, 건너뜀 |
| 차선 또는 Depth 시각이 역행 | 건너뜀 |

수명·좌표계·동기화·계획 유효성 검사는 유지한다. 정상 범위의 중복/역행 계획은
이미 수락한 경로를 지우거나 입력 수명을 연장하지 않는다. checked 모드의 확인
횟수는 계속 서로 다른 Depth 촬영본에서만 증가한다.

## 3. 장애물 투영 광선 캐시

해상도/ROI/stride/내부 파라미터로 정해지는 정규화 광선을 캐시한다. 이 키가
바뀔 때만 다시 만든다. 매 프레임의 RGB/IMU 자세는 계속 적용하며, raw depth가
유효한 표본만 회전시킨다. 원래의 좌표 연산 순서와 높이·지면·거리·표본 판정을 유지한다.

## 4. 표시 준비·BEV 다운로드 분리

- 차선 추론·레이블·중앙선·정지선 거리·결과 발행은 기존 처리 빈도로 계속 수행한다.
- 연결/경계 기하 계산용 플래그는 유지하고, BGR 그림과 표시용 마스크/스냅샷만
  프리뷰 FPS로 준비한다. 외부 결과 영상 구독자는 기존 결과 영상 빈도를 유지한다.
- direct GPU BEV에는 캐시된 host download 함수를 함께 제공한다. 원본 오버레이를
  실제 그리는 GUI 스레드에서만 다운로드한다. 같은 프레임은 `call_once`로 한 번만 복사한다.
- 다운로드는 BEV 처리 스트림과 별도의 nonblocking 스트림을 사용한다. 전역 CUDA
  동기화나 추론 스레드에서의 CPU 다운로드를 추가하지 않는다.
- 함수는 GPU 버퍼와 downloader 소유권을 보관한다. 프리뷰가 늦어지거나 BEV
  프로세서가 재설정돼도 해당 촬영본의 버퍼가 재사용/해제되지 않도록 한다.
- 캡처도 같은 촬영본의 cached download를 사용한다. 명시적 ROS 영상 발행·데이터셋
  저장·독립 BEV 프리뷰가 요청하는 기존 eager host 출력은 유지한다.

## 확인 범위

사용자 요청대로 빌드·단위 테스트·시뮬레이션·실차 테스트를 실행하지 않았다.
소스 변경 및 Git diff/공백 오류만 검토했다. 공유 handoff 헤더가 바뀌므로 pull 뒤
`bev_handoff`, `bev_processor`, `line_detactor`, `auto_control`을 함께 재빌드해야 한다.

## 5. 추가 효율화 (빌드·실차 미검증)

- **빌드**: `CMAKE_BUILD_TYPE` 미지정 시 Release를 기본으로 한다.
- **Depth 투영**: 프레임마다 할당하던 표본/지지 버퍼를 재사용하고, 광선 테이블을
  행·바이트 오프셋 + `float` 방향(12바이트)으로 줄였다. `hypot` 대신 `sqrt`,
  `z <= ground.distance_m`인 바닥 픽셀은 거리 계산 전에 제거한다. 방향을 `float`로
  저장하므로 bin 경계의 표본은 이전과 미세하게 다를 수 있다.
- **`obstacles.points.max_depth_m` 20 → 3**: `range.max_m`(2m) 밖 픽셀을 좌표 변환 전에
  버린다. `range.max_m`을 키우면 함께 키운다. 로그의 제거 카운터 값만 달라진다.
- **장애물 worker**: 1ms polling 대신 `bev_handoff::waitDirectDepth()`로 새 Depth를
  기다린다(만료 처리를 위한 20ms 상한). RGB 자세를 기다릴 때만 2ms 간격으로 재시도한다.
  `bev_handoff` 헤더가 바뀌므로 관련 패키지를 함께 재빌드한다.
- **주행 CSV**: 기본 꺼짐. 스칼라 9자리, 중앙선 좌표는 소수 4자리(0.1mm)로 기록한다(schema 9).
- **터널 선택기**: 차선 결과를 raw 바이트로 받아 촬영 시각만 읽고 그대로
  `/tunnel/lane_result/{rgb,ir}`로 전달한다. 제어기는 두 토픽을 직접 구독한다.
- **차선 내 장애물 판정**: 변형 계획이 이미 계산한 차선 소속 결과를 재사용한다.
  판정 기준이 원본 중앙선에서 계획용 재샘플 경로(`path_minimum_x..maximum_x`)로 바뀐다.
  계획이 판정을 수행하지 못한 경우(CHECKED 모드, 중앙선 입력 대기)는 기존 함수를 쓴다.
- **회피 계획 수신**: 계획은 저장만 하고 제어 명령은 다음 차선 결과에서 계산한다.
  회피/감속 반영이 최대 차선 한 프레임 늦어진다. CHECKED 모드의 guard stop은 즉시다.
- **진단 토픽**: 구독자 수 조회를 1초마다 한 번으로 줄였다. 새 구독자는 최대 1초 뒤부터 받는다.
- **GUI**: runtime tools는 창이 없을 때 50ms 주기, 표 갱신 4Hz. 시작 점검 화면은 10Hz
  (속도 슬라이더 조작 중에는 기존 주기)로 그린다.
