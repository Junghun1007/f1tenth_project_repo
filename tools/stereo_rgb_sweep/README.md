# 정지 상태 RGB·스테레오 파라미터 탐색

이 폴더만으로 실행하는 독립 도구다. `COLCON_IGNORE`로 기존 colcon 빌드에서 제외한다. OAK를 직접 열어 측정하며 VESC·조향·START·STOP 인터페이스와 연결하지 않는다. 결과를 검토한 뒤 필요한 설정을 주행 코드에 별도로 반영할 수 있다.

## 기본 실행

차량을 정지하고 기존 카메라·주행 프로그램을 종료한다. Jetson의 저장소 루트에서 실행한다.

```bash
git pull --ff-only origin 1030ML
python3 tools/stereo_rgb_sweep/sweep.py
```

첫 실행에서 측정 프로그램을 자동 빌드한다. 기존 `/usr/local` DepthAI C++ SDK 3.6 이상, CMake, C++17, OpenCV core/imgproc/calib3d, Python 3를 사용한다. Python depthai나 pip 패키지는 필요하지 않다. SDK 위치가 다르면 `--sdk-prefix`를 지정한다.

```bash
python3 tools/stereo_rgb_sweep/sweep.py --sdk-prefix /usr/local
```

## 탐색과 재측정

기본 실행은 전체 고정 조합을 짧게 탐색한 뒤 상위 후보를 길게 재측정한다.

| 단계 | 기본 설정 |
|---|---|
| 전체 탐색 | 고정 조합 576개, 준비 2초 + 측정 5초, 각 1회 |
| RGB 대조군 | 장치 보정·호스트 보정의 RGB 단독 및 마지막 RGB 단독, 총 3회 |
| 후보 선정 | 최소 깊이/ROI 수신 10 Hz 이상인 후보에서 최대 6개 |
| 후보 재측정 | 후보마다 고정·FPS 전환·해상도 전환을 각각 60초씩 |

호스트 보정·전송 형식마다 대표 후보를 먼저 선택하고 남은 자리를 순위순으로 채운다. 따라서 깊이 영상·시차·요약 좌표 중 특정 형식만 모든 후보를 차지하는 것을 피한다. 기본 준비·측정 시간 합계는 최대 약 86분이며 장치 재연결·빌드·실패 시간은 추가된다. 실행 시 예상 시간과 전체 진행 수를 출력한다. 전체 조합을 확인하는 데 걸리는 시간은 고정 조합 수에 비례한다.

```bash
python3 tools/stereo_rgb_sweep/sweep.py --dry-run
```

`--dry-run`은 전체 계획만 출력한다. 탐색 시간과 최종 후보 수를 바꿀 수 있다.

```bash
python3 tools/stereo_rgb_sweep/sweep.py --screen-duration 3 --top 3
```

`--duration`은 최종 후보의 측정 시간이며 기본 60초다. `--repeats`는 전체 탐색 반복 수이며 기본 1이다. `--dot-intensity`는 모든 조건에 적용하는 IR dot 강도이며 기본 0.7이다. projector가 없는 장치는 0으로 지정한다.

## 비교하는 고정 조합

| 항목 | 값 |
|---|---|
| 깊이 요청 FPS | 10, 20, 30, 40 |
| 스테레오 영상 크기 | 640×400, 512×320, 320×200 |
| 좌우 일관성 검사 | ON, OFF |
| 중앙값 필터 | 3×3, OFF |
| 전송 형식 | 16비트 깊이, 8비트 시차, OAK에서 계산한 24개 ROI 좌표 |
| RGB 렌즈 보정 위치 | OAK / 젯슨 OpenCV CPU |
| 스테레오 가로 ROI | 전체 폭 / 중앙 50% |
| 스테레오 세로 ROI | **하단 65% 고정** |

4×3×2×2×3×2×2 = 576개다. RGB 요청은 항상 1280×800 NV12·80 FPS다. 스테레오 센서 모드는 640×400이고 출력 크기를 바꾼다. 고정 조건의 센서·출력 FPS는 해당 깊이 요청 FPS로 설정한다. 서브픽셀·확장 시차·추가 공간/시간 필터는 OFF, FAST_DENSITY, confidence 200, LR threshold 10, IMU 400 Hz, 최신 프레임 큐, XLink chunking OFF를 사용한다.

ROI는 영상 하단에서 위로 65%로 해석한다. 양쪽 영상에서 같은 영역을 **매칭 전에** 크롭한다. 중앙 50%는 정지 실험용 고정 중앙 영역이며 실제 차량 경로를 추적하지 않는다. 코너 주행 적용 시 시야와 경로 범위를 다시 검토해야 한다.

16비트 깊이는 OAK에서 깊이를 계산해 전달한다. 8비트 시차는 서브픽셀 OFF의 시차를 받아 젯슨에서 매 프레임 `초점거리×베이스라인/시차`로 거리를 계산한다. 두 조건 모두 0.1~3 m 유효 비율을 기록한다. 거리 제한은 계산 후 필터라서 매칭 범위 자체를 줄이지 않는다.

좌표 요약은 전체 깊이를 전송하는 대신 OAK의 SpatialLocationCalculator에서 8×3 영역의 최소 깊이 기반 XYZ를 전송한다. 수신 Hz는 ROI 좌표 메시지의 빈도다. 장애물 윤곽·높이·지면 제거가 필요한 기존 검출 결과와 정보량이 다르다. 각 메시지의 24개 좌표는 별도 파일에 남긴다.

젯슨 보정 조건은 raw RGB 수신과 별도 최신 프레임 worker에서 **CPU BGR 변환·렌즈 보정**을 수행한다. 수신 Hz와 보정 완료 Hz를 각각 기록한다. CUDA 보정 성능을 측정하는 조건은 포함하지 않는다. 보정된 픽셀의 시야와 현재 BEV의 보정 방식 일치는 별도 검증 대상이다.

## 전환 실험

정지 상태 파라미터 비교이므로 타이머로 장애물 후보 등장·해제 상황을 재현한다. 실제 장애물 검출기나 자동 회피와 연결하지 않는다. 각 60초 실험을 감시 20초 → 강화 20초 → 감시 20초로 나누며 프레임과 phase별 처리율을 남긴다.

- `fixed`는 선택된 후보 설정을 그대로 60초 유지한다.
- `fps_burst`는 좌우 센서 40 FPS를 유지하고, 같은 촬영 시퀀스의 영상 쌍을 장치 Script에서 매칭 전에 제한한다. 후보의 FPS가 10/20/30이면 해당 값 → 40 → 해당 값으로 전환한다. 40 FPS 후보는 30 → 40 → 30으로 비교한다. 센서·ISP는 계속 40 FPS이므로 저속 센서 고정 조건과 구분해 해석한다.
- `resolution_burst`는 같은 센서 영상 쌍을 작은 입력용/큰 입력용 두 StereoDepth 분기 중 하나로 보낸다. 작은 입력은 320×200, 큰 입력은 후보의 512×320 또는 640×400이다. 후보가 320×200이면 큰 입력을 640×400으로 비교한다. FPS는 후보의 값으로 유지한다. 두 StereoDepth 노드의 자원 할당을 포함하므로 RVC2에서 분기 2개를 지원하지 않거나 자원이 부족하면 실패로 기록한다. 파이프라인 재시작 없이 전환하는 실험이다.

전환 명령과 프레임 도착 사이에는 기존 파이프라인 지연이 있다. phase는 호스트의 요청 상태 기준이며, 실제 프레임 크기와 촬영 시각을 함께 기록한다. FPS gating으로 건너뛴 시퀀스도 `sequence_gaps`에 포함되므로 전송 손실로 단정하지 않는다.

## 결과와 순위

저장 위치는 `tools/stereo_rgb_sweep/results/날짜_시각/`이다. 각 측정 종료 시 요약을 갱신한다. 최초 대조군에서 성공한 장치 ID를 이후 조건에 고정한다. 스테레오 조건 실패는 로그에 남기고 다음 조건을 실행한다. 기본 RGB 단독 장치 보정 조건까지 실패하면 중단한다. Ctrl+C로 중단하면 완료된 조건을 보존한다.

| 파일 | 내용 |
|---|---|
| `plan.json` | 전체 탐색 계획과 예상 측정 시간 |
| `finalists.json` | 선정된 후보와 전환 재측정 계획 |
| `screen_ranking.csv` | 전체 탐색 순위 |
| `confirm_ranking.csv` | 후보 고정/전환 재측정 순위 |
| `results.json` | 모든 완료·실패 결과, phase별 Hz, 호스트 연산 시간, OAK CPU·메모리·온도 |
| 각 조건의 `config.json`, `console.log`, `result.json` | 설정, SDK 오류 로그, 개별 결과 |
| 각 조건의 `rgb_frames.csv`, `depth_frames.csv` | 수신·촬영 시각·시퀀스·지연·실제 크기·phase |
| 좌표 전송 조건의 `spatial_samples.json` | 메시지별 24개 ROI의 XYZ(mm) |

우선 순위 기준은 **모든 측정 phase에서 실제 깊이/ROI 수신 10 Hz 이상**이다. 요청을 10으로 했더라도 실측이 10 미만이면 기준 미달로 표시한다. 짧은 탐색은 프레임 수 양자화와 전달 지터의 영향을 받으며 60초 재측정으로 재확인한다. 호스트 보정 조건은 RGB 수신률과 보정 완료율 중 낮은 값을 `usable_rgb_hz`로 사용한다. 이후 사용 가능한 RGB 처리율이 높은 순서, 평균 수신 지연이 낮은 순서로 정렬한다.

깊이 유효 비율은 매초 한 영상에서 0.1~3 m 값을 가진 픽셀 비율이다. 좌우 검사를 끄면 잘못된 깊이도 유효 값으로 남을 수 있다. 좌표 요약 조건은 밀집 깊이의 유효 픽셀 비율이 없으므로 null로 기록한다. 순위가 높다는 사실만으로 장애물 검출 정확도를 보장하지 않는다.

결과 폴더 전체를 압축해 전달한다.

```bash
tar -czf stereo_rgb_sweep_results.tar.gz -C tools/stereo_rgb_sweep results
```
